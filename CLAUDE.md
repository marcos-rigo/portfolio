# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

This repo was migrated from a static Gulp/SCSS/Bootstrap site to a Next.js 16 App Router application (see `IMPLEMENTATION_PLAN.md` for the original migration brief, in Spanish). The legacy `gulpfile.js`, `scss/`, `css/`, `font-awesome/`, jQuery-based `js/`, and the static-site `index.html` have been removed — the app is entirely under `src/`.

## Commands

- `npm run dev` — start the Next.js dev server (Turbopack default in Next 16)
- `npm run build` — production build
- `npm run start` — serve the production build
- `npm run lint` — ESLint (flat config via `eslint.config.mjs`, `eslint-config-next` core-web-vitals + typescript rulesets)

There is no test suite configured.

## Architecture

Single-page portfolio (`src/app/page.tsx`) composed of client components rendered in a fixed order inside one `<main>`: `CanvasBackground` → `Navbar` → `CommandMenu` → `Hero` → `AboutBento` → `ExperienceTimeline` → `SkillsGrid` → `PortfolioDeck` → `ContactForm` → `Footer`. All section text renders directly (no client-only loading gate), so it is present in the initial server-rendered HTML for crawlers/link previews. `CanvasBackground` is purely decorative and is lazy-loaded client-side via `next/dynamic` with `ssr: false`, and no-ops when the user has `prefers-reduced-motion` set (`hooks/use-reduced-motion.ts`) — it renders zero `<canvas>` elements in that case. No routing beyond this single route; `robots.ts`, `sitemap.ts`, and `opengraph-image.tsx` are the only other app routes.

**`Hero` (`src/components/hero.tsx`) + `HeroPhoto` (`src/components/hero-photo.tsx`):** the Hero's right column renders a circular framed portrait (`/img/foto-perfil.jpeg`) instead of a decorative canvas. `HeroPhoto` builds the frame from theme tokens only — a rotating conic-gradient ring (`.hero-photo-ring` / `.animate-hero-ring-spin` in `globals.css`, navy → red → gold), a thin gold detail ring, layered shadows for relief, a breathing ambient glow (`.animate-hero-breathe`), and small floating chips (`.animate-hero-float`) — and applies pointer tilt via the shared `use3DTilt` hook (destructure its return value before spreading onto JSX — passing `hook.ref` inline trips the `react-hooks/refs` lint rule). All of the above is skipped when `usePrefersReducedMotion()` is true, leaving a static framed photo. Separately, `Hero` drives a scroll-linked "zoom" on the photo (desktop `≥lg` only, and only when motion isn't reduced): `useScroll`/`useTransform`/`useSpring` from Framer Motion scale the photo from ~1.28 down to 1 as the user scrolls through the Hero section (`target: sectionRef, offset: ["start start", "end start"]`); only `transform` (`scale`/`y`) is animated, so it causes no layout shift, and a `matchMedia("(min-width: 1024px)")` listener gates the effect off on mobile/tablet, where the photo just renders at a fixed moderate size.

**Providers (`src/app/layout.tsx`):** `ThemeProvider` (next-themes, class-based dark/light, `defaultTheme="light"`, `enableSystem`) wraps `LanguageProvider` (`src/components/language-provider.tsx`), which wraps the page. Layout also injects `Person` JSON-LD structured data built from `personalInfo`.

**Content is centralized, not hardcoded in components:**
- `src/lib/data.ts` — typed content: `personalInfo`, experience items, skills, projects. Update this file (not individual components) when changing bio/project/skill copy.
- `src/lib/translations.ts` — `es`/`en` copy keyed by `TranslationSchema`, consumed via `useLanguage()` from `language-provider.tsx`. The language provider persists the chosen locale to `localStorage` (`marcosrigo-locale`) and falls back to `navigator.language`.
- **Experience data split across both files:** `ExperienceItem` (`data.ts`) is locale-agnostic — `{id, current, stages: ExperienceStage[]}`, where each `ExperienceStage` (`{id, current, technologies[]}`) holds only the tech-chip list and an ongoing flag, most-recent-stage first. All copy (company, `companySubtitle`, item- and stage-level `period` strings, role, `bullets[]`) lives in `translations.ts` under `experience.items[itemId]` / `.stages[stageId]`, keyed by the same ids as `data.ts` — this is why period strings are duplicated per locale (`"2016 – Presente"` vs `"2016 – Present"`) instead of being computed from dates. A single item can hold multiple stages to show a role progression within the same organization (see `exp-ministerio`, which nests `stage-fullstack` over the older `stage-web`); single-stage items (`exp-freelance`) render without the inner sub-timeline connector. `experience.currentLabel` drives the "Actual"/"Current" pill shown next to an item's period when `current: true`.

**Styling:** Tailwind CSS v4 via `@tailwindcss/postcss` (no `tailwind.config.*` — theme tokens are defined inline in `src/app/globals.css` using `@theme` + CSS custom properties for light/dark color pairs: `--background`, `--foreground`, `--primary`, `--muted`, `--card`, `--border`, `--accent`, etc., consumed as `bg-background`, `text-foreground`, `bg-primary`, and so on). The palette follows a CV-inspired identity — white/cream surfaces, navy (`#16355C`) as the structural/text color, red (`#D81F2A`) as the primary accent for pills/buttons/links, and a small gold accent (`#F5C84C`) reserved for icons/details only. Dark mode swaps to a navy background (`#0E2440`) with cream text, same red/gold accents. Never hardcode colors from the old removed neon palette; always read from the CSS custom properties (or their Tailwind `bg-*`/`text-*` equivalents) so both themes stay in sync. Fonts are loaded via `next/font/google` in `layout.tsx`: Poppins for both body and headings (exposed as `--font-sans`/`--font-heading`), Geist Mono for monospace/data displays (`--font-mono`).

**`SectionHeading` (`src/components/section-heading.tsx`):** reusable red-pill section header (`tag` + `title` + optional `description`) used at the top of Experience, Skills, Portfolio, and Contact sections — reuse it rather than hand-rolling section headers. Its `<h2>` uses the `.heading-section` clamp utility.

**Layout system (all sections except Hero, which manages its own layout):**
- **`.container-wide`** (`globals.css`): the shared content-width utility — `max-width: 1440px` (`1600px` at `2xl`), fluid side padding (`1rem` mobile → `2rem` at `lg` → `3rem` at `xl`). Applied to every section's `<section>` tag, the navbar's floating pill (`max-w-[1440px]`), and the footer grid, so everything lines up at any breakpoint. Don't reintroduce `max-w-5xl`/`max-w-6xl` — use this class instead.
- **Typography scale:** `html` font-size is 17px on mobile, 18px on `lg+` (`globals.css`), so all `rem`-based Tailwind text utilities scale up together; never drop a text size below `text-sm` (14px baseline) for anything meant to be read as body copy — arbitrary pixel sizes like `text-[9px]`/`text-[10px]` don't scale with the root and are reserved for decorative SVG micro-labels (e.g. the About radar chart, portfolio architecture diagrams). Section titles use `.heading-section` (`clamp(2rem, 1.55rem + 2vw, 3.25rem)`); card/major titles use `.heading-card` (`clamp(1.2rem, 1.02rem + 0.85vw, 1.65rem)`) — both fluid, no breakpoint jumps.
- **`.card-surface`** (`globals.css`): the shared "card with presence" treatment — tinted gradient background, a visible 1px border, layered box-shadows, and a hover state (desktop/`hover:hover` media only) that lifts the card (`translateY(-4px)`), reddens the border, and deepens the shadow into a red-tinted glow. Only `transform`/`box-shadow`/`border-color` transition (~260ms), and the hover lift is disabled under `prefers-reduced-motion`. Used on the About bento cards, the experience timeline card, portfolio project cards, and the contact info/map/form cards — apply it instead of hand-rolling `bg-card border border-border shadow-* hover:shadow-*` per card.
- **`.section-surface` + `.section-surface-a` / `.section-surface-b`** (`globals.css`): alternating section backgrounds. Every non-Hero section gets `section-surface` plus either the `-a` (warm radial glow, primary-tinted) or `-b` (cool vertical navy wash with a gold/red radial accent) variant, alternating down the page (About=b, Experience=a, Skills=b, Portfolio=a, Contact=b) so sections read as distinct without a hard seam — implemented as an absolutely-positioned `::before`/background at `z-index: -1` inside an `isolate` section, so it adds zero layout shift. Both variants have dark-mode counterparts that lighten off the base navy instead of changing it.
- **`.clock-fluid`**: fixes the Local Time widget's `es-AR` time string (`"05:40:42 p. m."`) wrapping mid-string in the About "Ubicación" card — `white-space: nowrap` + `font-variant-numeric: tabular-nums` + a `clamp()` font-size so it always fits on one line at any card width.

**Interactive/visual components** worth knowing about before touching them: `canvas-background.tsx` (animated canvas backdrop), `hero-photo.tsx` (see above), `command-menu.tsx` (⌘K/Ctrl+K palette, has a hidden retro-terminal mode with `/help`, `/about`, `/skills`, `/contact`, `/theme`, `/cv`, `/clear`, `/exit` commands), `magnetic.tsx` and `hooks/use-3d-tilt.ts` (pointer-driven hover/tilt effects used by cards across the timeline/portfolio sections), `tech-playground.tsx` (used inside `SkillsGrid`), and `footer.tsx` (full-bleed footer with quick nav, contact/social links, and a smooth-scroll handler mirroring the navbar's anchor scrolling).

**Public assets:** `public/` (images under `public/img/`, favicon, and `public/cv.pdf` — see TODO below).
